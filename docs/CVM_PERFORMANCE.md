# Текущая CVM: ускорение без смены профиля и технический долг

20 сентября 2026. Исходная версия для сравнения:
`c4c941a49206f44a382f3153926ed30624d49086`.
Этот пакет исправляет действующий executor v2.2; реализация Full CVM и включение
AS2 production в него не входят. Единственные владельцы исполнения и прежние
границы Gold/памяти сохраняются.

## Выполнено сейчас

### Сериализация перехода

`CognitiveVM` переиспользует неизменяемые фрагменты прежнего JSON preimage.
Ключ включает содержимое и типы скалярных operands, имена locals и содержимое
стеков контекста/актора/политики. Он не использует адрес объекта. Значения
`True` и `1` различаются. Счётчики, previous hash и представление верхушки
стека вычисляются заново на каждом шаге.

Кэш принадлежит экземпляру VM, ограничен 128 записями; фрагменты длиннее
16 384 ASCII-символов не сохраняются. Он не входит в snapshot и не создаёт
authority. Составные operands, непустые mailbox, pending receive и нестандартные
типы продолжают проходить через общий JSON encoder. Кэш mutable значений не
создаётся. Кодировщики step и resume сохраняют каждый свой прежний формат,
включая пробелы resume. SHA-256 вычисляется на каждой положенной инструкции;
gas, порядок переходов и canonical bytes не меняются.

### Детерминированная компиляция циклов

`CognitiveCompiler` выделяет временные имена по порядку обхода AST, без `id(node)`.
В имени присутствует символ, недопустимый в исходном идентификаторе: временная
переменная не затрёт пользовательскую `__iter_0` или `__idx_0`. Повторный вызов
одного compiler создаёт новые буферы и не меняет ранее возвращённую программу.

У **заново скомпилированных** циклов меняется содержимое bytecode и, закономерно,
program hash. Прежние имена и hashes уже сохранённых программ не переписываются.
Формат и команды байткода остаются v2.2. Сохранённый старый bytecode продолжает
исполняться с прежними transition hashes. При необходимости перекомпиляции
исходника нужно заново связать новый артефакт с его проверкой/допуском; нельзя
подменять им bytecode старого replay или объявлять несовпадающие hashes равными.

### Лимит инструкций

Компонентный `CognitiveVM.run(max_steps=...)` остаётся ограниченным вызовом:
`halted=false` разрешает владельцу продолжить ту же VM; состояние и gas сохраняются.

Application-вызов `run vm` через `VMBridge` теперь возвращает явный
`error="STEP_LIMIT_REACHED"`, `halted=false`, число выполненных шагов и snapshot,
если остановился на пределе 10 000 инструкций. Контексты закрываются по пути
ошибки `VMStepLimitExceeded`, а не с ложной причиной `vm_halted`.
Остаток газа не означает завершение задачи. OUT_OF_ENERGY остаётся отдельным
исходом. Обработка существующих Host/message suspensions не изменяется.

Как и у OUT_OF_ENERGY, отказ представлен значением языка. Успешный exit code
CLI-процесса сам по себе не является доказательством успеха вложенного `run vm`;
потребитель проверяет result/error и соответствующий контракт остановки.
Автоматический scheduler, который продолжает длинные программы по квантам,
не добавлен скрыто под этим исправлением.

## Проверка и воспроизводимый замер

`tests/test_cvm_transition_encoding.py` проверяет каждый переход против прежней
формулы JSON/SHA-256, mutation/aliasing, bool/int, Unicode, большие/нестандартные
состояния, вытеснение фрагментов, snapshot/resume, стабильность compiler и чтение
прежнего bytecode. Отдельный файл
`acceptance/runtime/test_cvm_invocation_limits.py` проверяет chunked execution,
закрытие контекста при лимите, typed outcomes и канонический CLI.

Измеритель `scripts/benchmark_cvm_encoding.py` фиксирует программы старым compiler
и даёт обоим checkout **одинаковые байты программы** через существующий публичный
`run vm`, с одинаковым явным run_id через `attach_storage(None, run_id=...)`.
Новые случайные UUID разных запусков не сравниваются как один вход; поля истории
не удаляются из сверки. В каждом наблюдении проверяются независимый ответ, завершение, одинаковые
шаги/gas/transition hash и digest полного результата, snapshot и history.
Ускорение не засчитывается за более короткие новые имена или частичное исполнение.

Замер требует чистых checkout, использует несколько процессов, прогревы и
перемешанный порядок пар. Время включает создание Interpreter, разбор оболочки,
выполнение VM, snapshots и события application. Импорты, IPC измерителя и компиляция
исходника в байткод находятся вне замера. Это тёплое выполнение подготовленной
программы, не ускорение холодного CLI или всего агента.

```bash
python scripts/benchmark_cvm_encoding.py \
  --baseline /path/to/baseline --candidate /path/to/candidate \
  --out /path/to/cvm-results.json
```

`--corpus /path/to/previous-results.json` повторно использует ровно сохранённые
программы. Это ручной benchmark, не нестабильный timing gate CI.
### Наблюдаемый результат

Измерена чистая версия `8d144aa` против `c4c941a` на Linux / AMD EPYC 9V74,
Python 3.12.14, CPU affinity 0. Три процесса для каждой версии, два прогрева
и девять измерений каждого случая в процессе; итого 27 измеренных пар на случай.
Полные hashes исходников, замороженные программы и все samples находятся в
[cvm_encoding_performance_2026_09_20.json](cvm_encoding_performance_2026_09_20.json).

| Случай | До, медиана мс | После, медиана мс | Отношение до/после |
|---|---:|---:|---:|
| Арифметический for, 200 итераций | 33.336 | 29.689 | 1.123 |
| Арифметический for, 400 итераций | 74.622 | 66.704 | 1.119 |
| Арифметический while, 400 итераций | 40.596 | 35.489 | 1.144 |
| Вызовы функции, 150 итераций | 28.603 | 25.663 | 1.115 |
| Чтение массива, 200 итераций | 37.213 | 32.364 | 1.150 |
| Строки, 150 итераций | 22.791 | 19.643 | 1.160 |

Все 198 пар (396 исполнений, включая прогревы) совпали по семантическим
результатам. Уменьшение времени в отдельных случаях — примерно 10–14%; это
ускорение данного тёплого CVM-пути, не всех программ Synapse или LLM-агента.
Нативный runtime и устранение повторного полного хэширования крупного значения
по этим числам не заявляются. Хвостовые процентили на такой выборке не оцениваются.

Приёмочные результаты на том же production-коде:

- 848 проверок host runtime, CLI, CVM, consensus, snapshots и replay прошли.
- 495 целевых проверок CVM, compiler, Gold behavior/binding, replay adapter и
  OD-10 conformance прошли.
- 571 проверка архитектурных границ/ownership/dependencies и актуальной
  transition-encoding приёмки прошла.
- Gate разбора: 45 примеров; coverage корпуса 0.935620 при пороге 0.9332.

Наборы пересекаются, их числа не суммируются как уникальные тесты. Полный suite,
длительный эксперимент обучения памяти и production-приёмка AS2 не запускались:
изменения не затрагивают их владельцев. CI `host-runtime` включает отдельную
приёмку invocation limits; timing benchmark в CI-gate не превращён.

## Технический долг для следующей реализации

| ID / приоритет | Что осталось и почему сейчас не меняется | Владелец будущей работы | Условие закрытия |
|---|---|---|---|
| CVM-P01 / высокий | `repr` крупного значения и его полные байты всё ещё повторно входят в hash на каждой инструкции. Кэш фрагментов не устраняет квадратичный компонент циклов по большим спискам и растущим mailbox. | VM values + transition profile | Приняты versioned preimage, canonical value sharing и migration; старые цепочки не переписаны; цена измерена при независимом росте N шагов и M размера состояния. |
| CVM-P02 / высокий | Bytecode/Instruction остаются mutable. Полный кэш program hash или результатов verifier сейчас может устареть после изменения объекта. | Compiler + BytecodeVerifier | Неизменяемый VerifiedProgram, стабильные slots, ключи версий языка/ABI/gas/codec, проверка восстановленного кэша; новый запуск сохраняет policy/capability gates. |
| CVM-P03 / высокий | Python диспетчеризует инструкции и управляет Python-объектами. Нативное ядро и JIT не реализованы. | TransitionKernel | Один заменяющий executor; числовая семантика и ошибки совпадают; нет Python callback на каждой инструкции; differential gas/state/events/hash и replay приняты. |
| CVM-P04 / высокий | Application ограничен 10 000 инструкций за вызов; длинная программа теперь честно отвергается, но не продолжается автоматически. | Application execution + durable Scheduler | Явные terminal/yield/pending outcomes; resumable gas-bounded quantum; точные checkpoints, scopes и recorded effects; продолжение не удваивает события или вызовы Host. |
| CVM-P05 / средний | Существующая `vm_routing_cvm` — классификация AST, а не доказательство фактического исполнения opcode CVM. Менять историческую метрику молча нельзя. | Execution telemetry + compiler lowering | Taken-path учёт реального executor с объявленной версией метрики; завершённые задачи и частичные прогоны разведены. |
| CVM-P06 / средний | История изменяема; arbitrary immutable-value cache, O(1) trace head и suffix restore пока нельзя считать корректными без владельца ревизий. | EventJournal + persistence/projections | Один append-only logical owner, exact prefix/revision bindings, crash/replay эквивалентность; упаковка при одинаковом WAL+FULL и без переноса commit boundary. |

P01–P03 требуют архитектурных решений до production-кода, а не отключения
доказательств в режиме «fast». JIT/fusion не должны менять место исчерпания газа,
ошибку среднего шага, эффекты, видимые промежуточные переходы или восстановление.
Для соответствующих решений применимы specialization/guards из CPython PEP 659,
один источник определений инструкций из PEP 744 и различие deterministic fuel /
operational interruption в Wasmtime; версии и provenance фиксируются при принятии
конкретной зависимости. Новый профиль хранения или нативный runtime сюда не
внесены. D1/D2 привычек и семантический поиск остаются самостоятельной работой
памяти; этот пакет не объявляет их исправленными.
