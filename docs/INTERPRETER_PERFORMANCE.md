# Ускорение host-интерпретатора Synapse

Оптимизации из отчёта «Synapse — Итоговая верификация» перенесены на рабочую
ветку `codex/stage4-stage16-acceptance`, поверх
`9452e449c681d312566bcfe1713bdc684dabb243`. Исходные `patch_boost*.py` и
исследовательская батарея из 211 случаев не входили в предоставленный пакет.
Реализация выполнена по описанным механизмам, с проверкой контрактов текущего
проекта. Приведённые ниже измерения относятся к этому переносу, а не являются
повторной публикацией чисел исследовательского отчёта.

## Перенесённые механизмы

| Пункт отчёта | Реализация в текущем проекте |
| --- | --- |
| P1 | `Environment.env_id` выделяется при первом обращении/сериализации. Каждое окружение сохраняет собственную идентичность; окружения итераций не переиспользуются. |
| P2 | Таблица запрещённых действий consensus создаётся один раз. Для девяти точных классов выражений пропускаются только заведомо пустые внешние проверки. Проверки вызовов и доступа к агенту сохранены. |
| P3 | SHA-256 исходника вычисляется лениво и сбрасывается при каждом присваивании `source_code`. |
| P4 | Девять часто встречающихся выражений имеют прямую диспетчеризацию. |
| P5 | Общий ограничитель итераций host-циклов `while`/`for`; исчерпание является ошибкой исполнения. |
| G | Неизменяемое решение маршрутизации v2.2 кэшируется по имени класса. |
| H | Адаптация: кэшируется вычисляемый запасной `trace_id`; поиск явного ID сохраняет чтение изменяемого журнала. Инкрементальный курсор не перенесён, поскольку не замечал бы правки старых событий при replay/rollback. |
| I | Gold импортируется только при вызове соответствующей команды CLI. |
| K | Признак оператора, требующего аудита маршрутизации, кэшируется по имени класса. |
| L | Семнадцать частых точных классов AST направляются в единственный обработчик каждого класса. Для подклассов сохранены прежние проверки `isinstance`; совпадения имени недостаточно. |
| M1 | Префикс `sha256:` сохраняется вместе с хэшем исходника. |
| M2 | Кэшируется маршрутизация v2.1; шаблоны причин fallback неизменяемы. В журнал по-прежнему попадают отдельные обычные JSON-словари. |
| N1 | Подсистема `change` загружается по обращению. Публичные привязки обработчика CLI сохранены. |
| N2 | LLM-типы и реализация импортируются при использовании; `record_source` — при запросе записи. |
| N3 | Backend интерпретатора создаётся при первом обращении. Настройки окружения фиксируются при создании интерпретатора; явно назначенный backend имеет приоритет. |

Кэши маршрутизации ограничены 256 ключами. Формат событий, порядок аудита,
учёт CVM, существующая политика consensus и сохранённая память не заменяются
параллельными реализациями. Обработчики AST перенесены из прежней цепочки в
методы; обе формы диспетчеризации вызывают те же методы.

## Ограничение циклов

По умолчанию `Interpreter` допускает 20 000 000 входов в тела host-циклов.
Один счётчик разделяют вложенные циклы и функции этого экземпляра. Изменить
лимит можно до его создания:

```bash
SYNAPSE_FUEL_LIMIT=300000 python -m synapse run program.syn
```

В Python: `Interpreter(loop_fuel_limit=300000)`. Допустимо целое число от нуля;
пустое, отрицательное или некорректное значение настройки отклоняется. Ноль
разрешает программы без входа в тело цикла. Ровно разрешённое количество
итераций может завершиться успешно.

После исчерпания `FuelExhaustedError` сохраняет ошибочный исход даже при
перехвате внутреннего исключения. Следующая оценка AST этим экземпляром также
отклоняется. CLI возвращает код 1; `main()` не превращает ошибку лимита в успех.
Повторные вызовы одного интерпретатора разделяют остаток лимита; новый
интерпретатор начинает с нового бюджета.

Это ограничитель host-циклов. Он не является общим sandbox, лимитом памяти,
таймаутом внешнего инструмента или заменой CVM gas. Счётчик не добавлен в
durable-снимки: сквозной бюджет между восстановленными процессами не заявлен.

## Проверка совместимости

- 128 проверок интерпретатора, CLI, ленивого backend, `change`, fallback,
  LLM gateway, golden replay и запретов consensus прошли.
- Дополнительный набор: 1332 проверки CVM, consensus, golden/dream/integrate
  replay, снимков агентов, durable execution, архитектурных границ Gold,
  Mini memory proposal и ProjectMemoryStore прошли. Наборы частично
  пересекаются; числа не суммируются как уникальные тесты.
- 12 проверок подключённого проекта, канонического CLI resume и команды
  одобрения прошли; ленивый импорт сохранил действующих владельцев операций.
- Новые отдельные проверки покрывают смену исходника, изменение/откат
  журнала, сериализацию ленивых ID, замыкания в отдельных окружениях,
  вложенные циклы, проглоченное исключение лимита, coroutine-вход и запуск
  канонического CLI без доступных необязательных подсистем.
- Ожидание текста `--help` исправлено: оно не учитывало уже существующую
  команду `project`. Это падение отдельно воспроизведено на исходном commit.
- Все 17 перенесённых тел обработчиков совпали с AST исходной реализации,
  за исключением явно добавленного списания бюджета циклов.
- Репозиторные gates прошли: 45 примеров разбираются; покрытие корпуса CVM
  0.935620 при минимуме 0.9332; запрещённых связей в ownership DAG Gold нет.

CI выполняет проверки интерпретатора и CLI отдельной задачей `host-runtime`
в workflow `Stage 4 Gold`. Скорость не является нестабильным порогом CI.
Полная тестовая батарея проекта и длительный четырёхзапусковый эксперимент
обучения памяти в этом пакете повторно не запускались.

## Воспроизводимый замер

`scripts/benchmark_interpreter_boost.py` сравнивает два checkout на девяти
программах. Для каждой версии выполняются три наблюдения в новых процессах,
порядок версий чередуется. Каждый результат сверяется с заранее заданным
ответом; ненулевой код, stderr или другой ответ прерывают измерение.

CLI-замер включает запуск Python и импорты. Замер `in_process` охватывает
публичный `run(source)` после импорта, включая разбор программы и создание
интерпретатора. LLM работает в mock-режиме. Проверяется физический путь
импортированного пакета, сохраняются revision и digest продуктовых исходников,
тексты программ, хэши ответов, все времена, минимумы и медианы.

```bash
git worktree add --detach /tmp/synapse-before 9452e449c681d312566bcfe1713bdc684dabb243
python scripts/benchmark_interpreter_boost.py \
  --baseline /tmp/synapse-before --candidate . \
  --repeats 3 --output /tmp/synapse-performance.json
```

Измерение 20 сентября 2026, Linux, Python 3.12.14, по три наблюдения.
Все 108 исполнений (9 программ × 2 режима замера × 2 версии × 3 повтора)
выдали ожидаемые ответы. Ни один результат не исключён из расчёта.

| Программа | CLI до, с | CLI после, с | Ускорение CLI | Ускорение in-process |
| --- | ---: | ---: | ---: | ---: |
| for_arithmetic_100k | 4.4507 | 0.6687 | 6.66× | 6.80× |
| while_arithmetic_100k | 6.7155 | 1.0370 | 6.48× | 6.41× |
| recursive_fibonacci_20 | 2.0927 | 0.3436 | 6.09× | 4.69× |
| empty_for_100k | 1.1902 | 0.1545 | 7.71× | 6.01× |

Отношение сумм медианных времён: **6.60× для CLI**, **6.00× для in-process**.
Геометрическое среднее отдельных ускорений: 6.77× и 5.30× соответственно.
Это наблюдения в одном окружении; универсальный коэффициент ускорения для
любого проекта, внешнего инструмента или LLM не заявляется.

[Сырые времена и программы](interpreter_performance_2026_09_20.json) сохранены
в репозитории. Оба checkout в момент замера имели HEAD `9452e449…`; кандидат
содержал ещё не закоммиченные изменения. Их различают полные
`product_source_digest` в JSON (кандидат `f4c877b3…`, база `66d1dbc4…`).

## Связь с памятью

Ускоряется исполнение DSL и запуск команд. Существующий точный профиль
повторного использования памяти сохраняет свои admission, C1 и независимый
oracle. Ускорение Python-интерпретатора не доказывает ускорение модели или
всего цикла решения задач. D1/D2, семантический поиск и обобщение привычек
этим пакетом не реализуются; их статус описан в
[инструкции памяти Gold](GOLD_KNOWLEDGE_INGESTION.md).
