# Operation Blackout: полевое испытание Synapse

## Что это

Многоэтапный сценарий расследования аварии в распределённой системе. Агенты
написаны на самом Synapse (`blackout.syn`), запускаются через канонический CLI
(`python -m synapse run`). Генератор (`gen.py`) строит случайный мир:

- 7–12 сервисов со случайным графом зависимостей (DAG);
- поминутную телеметрию ошибок с шумом и ложными всплесками ровно на пороге;
- журнал деплоев с ловушками: ранний и поздний деплой в тот же сервис, деплои в
  другие сервисы;
- поток алертов с дублями.

Агенты должны по сырым данным найти первопричину, зону поражения и виновный
деплой. Независимый оракол на Python (`gen.oracle`) считает правильный ответ, и
каждое заключение агента сверяется с ним.

## Какие узлы задействованы

| Этап | Конструкции Synapse |
| --- | --- |
| Триаж | `agent`, `send`, `receive` (FIFO-почтовый ящик), дедупликация |
| Анализ | функции, замыкания, обход графа, поиск первопричины, обратный обход |
| Корреляция | поиск виновного деплоя среди ловушек |
| Гипотезы | `debate ... judge ... rounds`, `fracture self into ... consensus ... integrate` |
| Память | `memory palace`, `recall`, `imprint`, `consolidate` |
| План | `intention cascade`, `plan weave` |
| Управление | `intent` + `declare intent`, `policy ... guard`, `claim`, `verify`, `consequence` |
| Действие | `send Ops.execute` через политики, `receive` подтверждений |
| Постмортем | транзакционный `integrate`: плохой черновик откатывается, верный фиксируется |
| Состояние дежурного | `affective state/event/threshold/modulation` |
| Привычки | `energy_pool`, `habit ... activate when { context }`, `context` |
| Перепроверка | `compile vm` / `run vm` с `checkpoint` и `resume_from`, сравнение с интерпретатором |
| Самоаудит | `reflect { filter type == ... }` по журналу исполнения |
| Durable | `spawn`, `suspend`, LLM-сигнал, `run --durable` / `resume` между процессами |
| Воспроизводимость | `run --record`, `replay --mock`, хеш-цепочка истории |

## Как запустить

```bash
python field_test/run_field_test.py --seeds 50 --incidents 4
```

Ключ Gemini не нужен: LLM работает в режиме `mock`.

## Результат последнего прогона (Linux, Python 3.13, 47 секунд)

```text
A. Корректность:  50 миров x 4 инцидента, 3800 выводов, 0 ошибок
B. Диверсии:      6 из 6 остановлены по правильной причине
C. Durable:       6 из 6
D. Replay:        4 из 7 (3 падения из-за одного дефекта, см. №1)
E. Пробы:         9 дефектов воспроизводятся
```

Полный вывод в `last_run.txt` и `last_results.json`.

### A. Корректность

На 200 случайных инцидентах агенты ни разу не ошиблись. Проверялось следующее:
первопричина, зона поражения (двумя независимыми методами), виновный деплой
среди ловушек, критичность, команды Ops, откат плохого постмортема, повторные
инциденты в памяти, бюджет ошибок (интерпретатор, VM и VM после resume
совпадают), а также число событий аудита: вердикты политик, сообщения, откаты и
коммиты транзакций, активации привычек, fracture.

### B. Диверсии (в настоящий поток внедрена одна ошибка)

| Диверсия | Чем остановлено |
| --- | --- |
| Зона поражения больше одобренной (во 2-м инциденте) | guard на `intent`; 1-й инцидент выполнен, 2-й и 3-й не тронуты |
| `DROP TABLE` в команде Ops | guard на `send` |
| Необратимый откат | guard на `intent` |
| `claim` с низкой уверенностью | `verify` |
| `send` внутри guard политики | чистота guard |
| `send` из `dream` | изоляция dream |

### C. Durable

Сценарий «LLM-сводка → одобрение человека → проверка здоровья» проходит
`PENDING → PENDING → PENDING → COMPLETED` в четырёх отдельных процессах ОС.
Все ветки (approve/deny, green/red) верны. Повторный сигнал получает
сохранённый ответ без изменения артефакта. Конфликтующий сигнал отклоняется с
exit 24, подделка исходника в артефакте — с exit 21.

## Найденные дефекты

| № | Серьёзность | Дефект | Где |
| --- | --- | --- | --- |
| 1 | **Высокая** | `imprint` и `intention cascade` ломают golden replay: ID создаются через `uuid4()`, `created_at` берётся из `time.time()`, оба значения не записываются как побочные эффекты. Одной строки `imprint` хватает для drift=3. Полный сценарий даёт drift=11. | `synapse/storage_backends.py:59,105`, `synapse/intention.py:12-13`, `synapse/memory.py:60` |
| 2 | **Высокая** | `imprint` внутри `dream` записывает в долговременную память, и запись остаётся после сна. `memory.write` и `send` в dream блокируются, `imprint` нет. Событие `dream_isolation_violation` не создаётся. | изоляция dream |
| 3 | Средняя | `run vm { resume_from ... }` внутри блока `context` перезаписывает стек контекстов хоста стеком VM. Выход из `context` падает с `Context mismatch`. | `synapse/runtime/vm_bridge.py:1685` (`sync_context_tracker_from_vm_state`) |
| 4 | Средняя | Аффективные пороги проверяются только после событий верхнего уровня. Внутри `fn main()` и любой функции порог не срабатывает до следующей инструкции верхнего уровня, поэтому для программы целиком в `main()` реактивный слой мёртв. | вычисление порогов |
| 5 | Средняя | Действие порога `reflect on self { ... }` (пример из спецификации) всегда падает: `No agent context for memory operation`. В журнал аудита при этом попадает только левая половина условия `a and b`, хотя логика вычисляет обе. | действия порогов |
| 6 | Средняя | `fracture ... consensus majority` не выбирает большинство: возвращает все позиции, включая позиции прерванных субагентов (`None`). Форма `consensus` зависит от стратегии: у `weighted` это `{positions, deaths}`, у `majority`/`unanimous` словарь позиций, так что пример из спецификации `consensus.positions.X` работает только для `weighted`. | `synapse/interpreter.py:3241` |
| 7 | Средняя | `distributed consensus` из `.syn` всегда возвращает `deferred`: источник голосов включается только Python-API хоста (`enable_actor_method_vote_source`), даже если у агента есть `fn consensus_vote`. | выбор источника голосов |
| 8 | Средняя (эргономика) | Нарушение политики в интерпретаторе нельзя обработать: `catch(GUARD_VIOLATION)` работает только в скомпилированном CVM. Агент не может сказать «отказано, иду по плану B», программа просто останавливается. | `parser.py:331`, интерпретатор |
| 9 | Низкая | В строках нет escape-последовательностей (`"\n"` печатается буквально, даже в `examples/full_demo.syn`). Нет многострочных строк, так что программу для `compile vm` приходится писать в одну строку. | `synapse/lexer.py` (`string`) |
| 10 | Низкая | В литерале `{k: 1}` ключ — строка `"k"`, а не значение переменной. Ошибка доступа выводится как голое `Error: 'real'`, без строки и типа исключения. | диагностика |
| 11 | Низкая | В `thought { step "...{topic}..." }` подстановка `{topic}` не выполняется (видно в выводе `examples/full_demo.syn`). | `thought` |

Чего нет в языке (это ограничения, не баги): `else if`, `break`, оператор `in`,
присваивание по индексу (`m[k] = v`; обходится через `setdefault`/`update`),
`round`. `--input-file` работает только с `--durable`. Durable-режим принимает
лишь подмножество языка (P2a): `agent()`-инстансы, палаты памяти и т.д. в нём
отклоняются с exit 25.

## Что не проверено и почему

- **Интеллект LLM.** Без `GEMINI_API_KEY` модель работает в mock-режиме, поэтому
  `debate`, `thought` и `llm` выдают заготовки. Сценарий построен так, чтобы
  правильность не зависела от ответов LLM. С ключом (`SYNAPSE_LLM_PROVIDER=gemini`)
  можно добавить этап, где первопричину ищет только LLM, и сравнить его с оракулом.
- **Сеть и миграция** (`migrate`, `synapsed.py`): прототип, в сценарий не включён.
- **Слой Gold / project / SWE-bench** (`synapse project ...`): отдельная большая
  подсистема, для неё нужен отдельный сценарий на реальном репозитории.
